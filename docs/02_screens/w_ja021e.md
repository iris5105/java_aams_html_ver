# W_JA021E 채권 특이채 권리행사 처리

- 메뉴: `00848` / `W_JA021E`
- 화면: `/views/subscriptionrights/w_ja021e` (`/views/w_ja021e` 별칭)
- 원본: `pb_recource/JA021/w_ja021e.srw`, `d_ja021e.srd`, `d_ja021e1.srd`, `d_ja021e2.srd`

## 조회와 화면 구성

상단 필터는 권리일자, 거래코드, 채권종목, 이자방법, KOSCOM구분·코드를 제공한다. 거래코드는 `dddw`의 `W_JA021E` 메타데이터를 사용하며 KOSCOM구분은 선택 거래코드에 종속된다. `F55` 및 그 외 거래의 코드검색 제한은 SRW 조건을 따른다.

권리일자는 회사별 작업일자로 초기화하고 `SCT0CG`에 해당 거래코드의 자료가 있는 날짜를 하이라이트한다. 초기 자동 조회와 필터 변경에 따른 업무자료 자동 조회는 하지 않는다. 필터·회사 변경 시 기존 그리드 자료는 유지한다.

위쪽 master 영역은 `d_ja021e1`의 행사가격, 전환시작일, 전환종목코드, 매도제한일을 읽기 전용 `span`으로 한 행에 표시한다. 아래 detailGrid는 `d_ja021e2`의 컬럼 순서·편집 허용·정렬·합계 정의를 따른다. 두 영역은 고정형 상·하 구조로 배치하며 splitter는 사용하지 않는다.

- `GET /api/subscriptionrights/ja021e/data`: 채권 전환정보 및 계좌별 행사 내역
- `GET /api/subscriptionrights/ja021e/dates`: 하이라이트 일자
- `POST /api/subscriptionrights/ja021e/save`: 변경·삭제 행 일괄 저장

조회 내역이 없고 특정 채권종목이 지정된 경우 SRW의 `SCM0CM` 보유내역 쿼리로 계좌 행을 준비한다. 임의의 신규 행 추가·복사는 제공하지 않는다.

## 계산 및 저장

행사액면을 수정하면 `TRUNC(행사액면 / 행사가격)`으로 전환주수를 구하고 전일종가로 전환금액을 계산한다. 최초 보유내역 준비 시 계산은 SRW의 보유 취득금액 기반 초기화식을 따른다. 서버에서도 보유액면 한도와 정수·음수 입력을 검증한다.

단주대금 없이 수령 체크할 수 없다. 수령 체크 시 DB 시스템일자를 사용하며 체크 해제 시 수령일자를 비운다. 과거 권리일자와 전체 채권종목 조회는 수정할 수 없고, `sury_protect`가 설정된 행은 단주대금·수령 상태 변경 및 삭제를 차단한다.

저장은 마지막 조회 조건과 변경된 행을 사용한다. 회사 변경 후 다른 회사의 자료를 편집·저장할 수 없다. 서버는 회사 접근 권한, 거래·이자·KOSCOM구분 코드를 검증하고 조회되지 않은 계좌나 임의의 행 키를 거부한다.

`SCT0CG`는 기존 `dailyadvisory.entity.Sct0cg`와 `Ja030cQueryDslRepository`를 재사용한다. 화면에서 필요한 컬럼만 엔티티에 확장하고 영속 엔티티의 해당 필드만 수정한다. `SCT1CG`·`SCT1CG_TR`의 단주대금 설정·수령·해제·삭제는 행사 내역과 동일한 트랜잭션으로 처리한다.

새로고침은 자료와 변경 상태를 비우고 필터를 초기화한다. 저장 성공 시에는 저장한 조회 조건으로 자료를 다시 읽는다. 엑셀은 공통 툴바에서 계좌별 행사 내역을 내보낸다.

## 검증

`Ja021eServiceTests`는 보유액면 초과, 보호된 수령 내역, 단주대금 없는 수령, 시스템 수령일자, 현금 원장 초기화, 과거 일자, 임의 계좌 변경, 전환금액 재계산, 타 화면 컬럼 보존, 신규 계좌 채번, 원장 삭제를 검증한다. 실제 Oracle 조회·저장 검증은 DB가 연결된 실행 환경에서 수행해야 한다.
